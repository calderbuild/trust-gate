TrustGate

用声誉做门禁，而不是记录声誉。

问题

AI agent 经济要起飞，但没人知道该不该信一个 agent。

现有方案——ERC-8004 声誉注册表：谁都能打分，唯一的检查是"你不能是 agent 自己"。没有验证机制。

2026 年一篇实测论文给出了硬数字：评价系统该满足的 4 个必要条件，全部不满足。

Xiong et al., 《Can Trustless Agents Be Trusted? An Empirical Study of the ERC-8004 Decentralized AI Agent Ecosystem》— arxiv.org/abs/2606.26028, 中译版 p.14（英文原文 p.12，§7.1）

解法

一条评价要算数，必须双方都签字确认。

agent 服务完 → 对方用私钥签字确认 → 验证通过 / 有争议

Agent 自己不能给自己写历史。

架构 + 门禁逻辑

三份职责分明的合约，四条铁律放行。

身份

AgentIdentity

登记 agent，只认活跃 / 已吊销。

记录本

ActionLedger

存交互记录。对方签字才算验证通过或有争议。

门禁

TrustGate

只读前两者。免费预检和真实链上验证，判断逻辑完全一致。

agent 已吊销→ 拒绝
任意一条有争议记录→ 拒绝（一票否决，不是好坏相抵）
零条验证通过→ 拒绝（历史不足）
其余情况→ 放行

诚实的局限性

已知边界，不是漏洞

防得住一个人撒谎，防不住两把钥匙其实是同一个人。

Agent 永远不能给自己签字确认——这个问题解决了。但如果同一个操盘手同时控制 agent 和对手方两个钱包，他仍然可以签出一份互相确认的假历史。

抓这种合谋需要质押 + 惩罚挑战机制——是另一套系统，一天内做正确的代价，是核心机制根本跑不通。这是主动公开的边界，不是被问到才承认。
